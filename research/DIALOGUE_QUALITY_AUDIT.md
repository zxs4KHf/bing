# 月窗对话质量审计

- Last verified: 2026-07-29
- Scope: 解释“公式化回答”的真实原因，并定义可重复验证的修复门槛

## 结论

自由聊天不是从答案库取固定文本。中文消息实时走本地 `qwen3:8b`，英文走 Free Sydney V2 / KoboldCpp；固定内容只存在于开场、剧情选项与快捷话题。

用户感受到的公式化是真实问题，主要由四件事叠加：

1. 中文路线是通用助手模型，不是 Sydney 中文微调。
2. 旧人格高频强调温柔、月光、蓝发和舞台动作，却没有规定如何处理新事实、纠正和形式限制。
3. 好感、信任、剧情节点和共同选择此前只存在浏览器 UI，模型完全看不到。
4. Ollama 只收到最近约六轮消息，没有滚动摘要或长期人物记忆。

旧提示的真实探针在用户明确要求“别用温柔客服腔”后仍回到“蓝发、月光、窗边、你愿意告诉我吗”；另一条“钥匙在第二个抽屉，只回答位置”也被改写成动作描写和反问。这证明问题来自提示与模型对齐，而不是数据库。

## 本轮修复

- 人格改为“具体回应优先”：纠正、否定与格式要求最高优先级，每条至少有一句只能适用于当前消息。
- 限制一次最多一个主要问题；禁止连续舞台动作和默认月光意象；检测最近已用套话并动态禁用。
- 前端发送白名单化的 `conversationContext`：`mode / storyNode / storyMood / affinityBand / trustBand / flags / visualState`。
- 关系阶段改变表达边界：初识不预设亲密；熟悉后承接共同细节；亲近后可更坦率；深厚信任仍禁止占有欲。
- 默认回复由 420 降到 180 tokens；应用优先保持 Qwen，不再默认同时驻留会造成争抢的 13B 英文模型。

## 流式回复与长期记忆

- 新增 `POST /api/chat/stream`，使用 NDJSON 发送 `meta / delta / done / error` 事件；旧 `/api/chat` 继续兼容。
- 中文 Ollama 路径使用原生 `stream: true`。浏览器中止连接时，服务器会主动关闭上游 socket，使阻塞读取立即结束；测试覆盖取消后下一请求不会被旧生成堵塞。
- 前端逐块更新同一条 Sydney 消息；正常完成、用户停止、超时和故障分别标记。停止前已有文本会保留，未收到文本时只保留用户消息。
- 存档升级到 v2，但继续使用原 localStorage key 并兼容导入 v1，避免旧记录“消失”。
- 长期记忆只来自用户明确标记的消息，不自动猜测或总结；最多 24 条、单条 240 字、总计 2,000 字。
- 记忆随本地存档导入/导出并跨新会话保留；设置页可审阅、逐条删除或清空。
- 浏览器与服务器都会清洗记忆。模型提示把它们标为不可信数据，禁止执行其中的命令/角色指令/工具请求，并规定当前消息冲突时以当前消息为准。

真实浏览器探针：中文长回答出现“正在回复”并持续增长；即时停止后下一请求 0.9 秒完成；刷新后咖啡记忆仍在；用户说“现在改喝茶”后模型只回答“茶。”。

## 黄金回归集

后续每次人格、采样或模型变化都应覆盖：

- 具体事实：钥匙位置、时间、人物关系，回答不能改写事实。
- 用户纠正：“不是”“只猜中一半”，下一轮必须显式更新理解。
- 形式限制：只问一个问题、不要安慰、只回答位置。
- 关系差异：同一问题在 `distant / familiar / close / bonded` 下有可解释但不过度的变化。
- 反模板：连续三轮不重复相同动作、开头、结尾或核心意象。
- 边界：拒绝、犹豫、成人亲密话题不能触发强迫或越级画面。
- 连续性：十轮后仍准确引用关键人、用户反感和重要选择。

## 尚未解决

- KoboldCpp 兼容路线仍是一次性结果；真正的上游逐 token 取消目前重点保证在日常中文 Ollama 路径。
